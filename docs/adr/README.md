# ADR 索引与规则

架构决策记录（ADR）用于记录跨模块、长期有效且仅靠代码不易看出的取舍。局部
实现细节、一次性排错和已验证小经验写入代码注释、测试或
[`lessons-learned.md`](../lessons-learned.md)，不要创建 ADR。

## 何时创建

当决定改变公共接口、配置/数据格式、并发模型、远程控制身份、HTTP 安全边界、
更新信任边界或兼容性承诺，且未来维护者需要理解“为什么”时创建 ADR。先搜索现有
ADR，避免重复或冲突；事实变化时更新原 ADR 的状态或补充新 ADR，不改写历史结论。

## 编号和状态

文件名使用三位递增编号和短横线标题，例如 `001-remote-control-identity.md`。
编号只在本目录内递增，已发布编号不复用。状态使用 `proposed`、`accepted`、
`superseded` 或 `rejected`。

## 最小模板

```markdown
# ADR-NNN: 标题

- 状态: proposed
- 日期: YYYY-MM-DD
- 相关组件: ...

## 背景
## 问题
## 可选方案
## 最终选择
## 选择原因
## 已知代价
## 后续影响
## 验证依据
```

ADR 必须链接相关源码、测试和架构文档；不得包含服务器地址、认证信息、私钥、
token 或个人绝对路径。提交前执行 Markdown 链接检查和事实核对。
