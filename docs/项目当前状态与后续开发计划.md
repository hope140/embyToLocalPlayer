## 1. 当前结论

当前 beta 修复已完成实际验收，并已整理为 `2026.09.11` stable 正式版。现阶段没有已知的阻断性缺陷。

本地 beta 随后增加了 ETLP 单实例和单活动播放窗口实现；该提交尚未形成新的远端
beta Release，也尚未进行新的真实 Emby/mpv 客户端验收。

本轮验收和发布覆盖了以下内容：

- 连续播放时逐集获取和传递章节，按实际媒体路径向 mpv/mpv.net 补入章节，并保留媒体原生章节。
- 不落盘 HTTP 预取独立于持久缓存下载器，失败时不阻断播放，也不创建缓存任务和锁文件。
- 更新配置只有新增分区时也能生成差异提示。
- 持久缓存 Range 下载先验证响应，再写入文件；错误响应不会覆盖已有缓存，短读可以从下一个字节继续。
- 用户脚本日志生成脱敏快照，动态标题、字幕、文件名和 STRM 路径使用文本节点。

## 3. 当前运行边界

ETLP 仍是本地播放辅助服务。浏览器脚本向本机 HTTP 服务发送请求，服务解析 Emby、Jellyfin 或 Plex 数据，选择本地播放器，并可选地使用 CloudDrive2 gateway、Emby 会话和远程控制通道。

当前约束保持不变：

1. 本地 HTTP 默认监听回环地址；非回环监听需要强 token。
2. Emby/Plex 请求必须先完成解析，再创建后台播放线程。
3. 远程控制失败时降级为普通播放和最终进度回传。
4. STRM 预热和 CloudDrive2 解析属于 best-effort，失败时保留原路径判断和回退逻辑。
5. `stable` 是稳定频道，`beta` 是测试频道，`main` 只用于上游同步。
6. 更新器按安装包频道选择 GitCode Release，失败时回退 GitHub，并校验 ZIP、sidecar 和可选 `release-plan.json`。

## 4. 下一阶段计划

### 阶段 A：发布收尾与短期观察

当前 beta 的验收结果已经转化为稳定频道正式发布，后续进入版本观察阶段。

- 观察 stable 的实际使用反馈和更新器下载情况。
- 保留上一稳定版作为回退版本。
- 确认正式版没有新增的播放、缓存、字幕、进度或更新问题。

正式版已按独立 stable 包、stable 脚本 URL、包内频道元数据、ZIP 哈希、sidecar 和 Release 资产完成核对。

### 阶段 B：实例与启动行为

阶段 B 的核心实现已在本地 beta 完成：

- ETLP 启动先取得跨进程实例锁，第二个实例直接退出。
- 启动阶段不再按进程名清理外部播放器，端口冲突不会触发未知进程终止。
- 播放分派使用单活动 playback lease，第二个请求返回 HTTP 409 `playback_busy`。
- 直接 `Popen` 播放器在进程退出前保持 lease，启动失败和异常路径会释放状态。

仍需用新的 beta 包完成快速退出、重复启动、端口冲突、再次播放和真实 Emby/mpv
客户端验收。历史 `/playMediaFile` helper 不属于这条主播放链路，暂未纳入单窗口保证。

### 阶段 C：播放失败反馈

当前前端错误提示仍较粗，后续需要把请求接收和播放器实际启动结果分开：

- 区分本地服务不可达、协议拒绝、配置无效、播放器路径错误、媒体打开失败和 CD2 回退。
- 为后台起播任务增加有限时长的状态反馈。
- 保留可操作的下一步，例如检查播放器路径、配置路径映射或重新启动本地服务。
- 避免把所有错误都提示为“本地服务未运行”。

### 阶段 D：更新安装恢复

现有更新器已经具备下载校验、ZIP 安全检查和配置保护，后续要解决替换过程的中断风险：

- 暂存解压并完成全部校验后再进入替换阶段。
- 替换前保存明确的旧版本备份。
- 对文件占用、磁盘空间不足和复制中断提供恢复路径。
- 下次启动时识别未完成更新并恢复到完整版本。
- 通过故障注入测试验证恢复和回滚。

### 阶段 E：Python 运行时评估

当前发布包继续使用 Python 3.9 x86 embedded runtime。迁移前需要独立比较 Python 3.13/3.14 的 Windows embedded 包、x64 兼容性、依赖 wheel、ctypes 行为、播放器进程管理和离线启动。

运行时迁移必须保留旧版回退包，不能和播放会话重构混在同一个版本中。

### 阶段 F：播放身份与传输模型

这是中期架构工作，按适配层逐步推进：

- 媒体身份使用服务器标识、ItemId 和 MediaSourceId。
- 每次加入播放列表生成独立 `entry_id`，允许同一媒体重复入列。
- 每次实际播放生成 `session_id`，集中持有停止、预取和进度状态。
- 分开描述 `source_kind`、`transport`、字幕来源和章节来源。
- 保留 `mount_disk_mode` 作为兼容适配，先补组合回归，再替换调用点。

在身份和状态模型迁移完成前，不对多播放器并行播放作能力承诺。

### 阶段 G：配置和模块整理

按收益逐步推进，不做一次性重构：

- 增加脱敏的轻量自检，检查配置文件、播放器路径、缓存目录、CD2 token/path_map、版本和频道。
- 明确代理的“自动、指定、直连”三种语义。
- 评估 `version_filter`、`enable_host` 和 CD2 配置模式的可读性与兼容规则。
- 将配置导入副作用逐步移出 `configs.py`。
- 按边界提取元数据获取、版本选择、预取、进度回传和播放器适配模块。
- 核查用户脚本 MIT 声明与仓库 Apache-2.0 许可证的来源和归属。

## 5. 推荐顺序和发布门槛

推荐顺序如下：

1. 观察并整理当前 `2026.09.11` stable。
2. 打包并验收 S46 beta 单实例和单播放窗口改动，再决定是否进入 stable。
3. 完善播放失败反馈。
4. 实现更新中断恢复并做故障注入。
5. 单独完成 Python runtime 兼容性评估。
6. 在组合回归保护下逐步迁移播放身份和传输模型。
7. 按实际收益整理配置和模块。

每个版本进入发布前都应满足：

- 相关自动化测试通过，且与上一版基线对比没有新增失败。
- Windows 打包、sidecar、Release plan 和包内频道元数据一致。
- 关键播放器和媒体路径完成适用范围内的验收。
- 发布后可从 GitCode 和 GitHub 下载同一 SHA-256 的 ZIP。
- 有明确的回滚版本和回滚步骤。

## 6. 当前不纳入计划的能力

以下能力不属于 ETLP 当前交付范围：

- 同步观看房间、参与者管理和跨设备跟随播放。
- 把本地 CD2 gateway 作为公网媒体服务。
- 豆瓣、Bangumi、Simkl、Trakt、聚合搜索或 qBittorrent 联动。
- 在没有身份和状态隔离前承诺多实例并行播放。
